# Int8 sleep-stage model, Fpz-Cz only

20 subjects, 20626 epochs, 5-fold leave-subjects-out (GroupKFold, the
same split as `reports/sleep_edf_baseline.md`). Generated by `scripts/train_sleep_model.py`.

**Input** (90 values): the 30 device epoch features, z-scored
per subject over the whole night (stand-in for the per-session calibration of REQ-FEAT-10), clipped
to ±6, for the current epoch and the previous 2.
**Model:** Dense(32,relu)-Dropout-Dense(16,relu)-Dropout-Dense(5,softmax), 3525 parameters, class weights
inverse sqrt frequency. Int8: full-integer post-training quantisation, representative set
from each fold's training subjects only.

## Cross-validated results (held-out subjects)

| Model | Accuracy | Macro F1 | Recall W | Recall N1 | Recall N2 | Recall N3 | Recall REM |
|---|---|---|---|---|---|---|---|
| Dense net, float | 0.796 | 0.739 | 0.83 | 0.50 | 0.80 | 0.84 | 0.81 |
| Dense net, int8 | 0.796 | 0.739 | 0.83 | 0.50 | 0.80 | 0.84 | 0.81 |
| Random forest, baseline (raw features) | 0.774 | 0.680 | 0.84 | 0.20 | 0.85 | 0.83 | 0.68 |
| Random forest, same input as the net | 0.813 | 0.737 | 0.87 | 0.31 | 0.87 | 0.75 | 0.84 |

Float/int8 agreement on held-out epochs: **99.20%** (REQ-ML-03 needs ≥ 98 %:
**PASS**).

Int8 model vs baseline random forest, macro F1: 0.739 vs
0.680 → **beats the random forest**
(accuracy 0.796 vs 0.774). A random forest given the
net's own input reaches macro F1 0.737, so most of the gain comes from the
per-subject standardisation and the previous-epoch context rather than from the net; the net's advantage
is N1 recall and a model small enough for the XIAO.

## Deployed model (`firmware/eeg_node/sleep_model.h`)

Trained on all 20 subjects for 11 epochs (median of the folds' early-stopping
points); float/int8 agreement on its training data 99.15%.

| Item | Value | REQ-ML-04 limit |
|---|---|---|
| `.tflite` size | 7,536 bytes | 65,536 bytes flash |
| Activations (sum of non-constant tensors) | 148 bytes | — |
| Arena estimate (11 tensors, 5 ops, with bookkeeping) | 3,156 bytes | — |
| Arena to allocate (2× estimate, ≥ 4 KB) | 7,168 bytes | 32,768 bytes |

Size and arena fit the limits on paper: **yes**. REQ-ML-04 also needs the
device measurement (arena used, µs per inference), which is task 4b.

The header also carries the input/output quantisation, the feature order, the clip value, and one
int8 test input per stage with the expected int8 output, for the on-device parity check.

## Caveats

- Standardisation uses each night's full mean/SD; the device will use ~60 s of calibration, which is
  noisier. Expect some loss on the device until this is simulated (e.g. stats from the first minutes).
- The previous-epoch stack assumes consecutive epochs; the cache keeps no onsets, so the few epochs
  dropped for missing windows (none in subject 0) join their neighbours across a gap.
